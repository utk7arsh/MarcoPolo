# FastAPI: minimum dashboard handoff

**Integration status, October 18:** the browser adapter is implemented in `server/marco/dashboard.py` and `dashboard_commands.py`, with routes in `app.py`. It runs alongside the device `/v1` API in [the team interfaces](../../docs/INTERFACES.md). HTTP, media and WebSockets retain the server's Tailscale identity gate.

The [original implementation plan](backend-integration-plan.md) records the preimplementation handoff. Use [STATUS.md](../../STATUS.md) for release results and remaining physical-device checks.

The frontend lives in `frontend/`. The [example fixture](dashboard.snapshot.example.json), [full contract](frontend-backend-contract.md), [generated JSON Schema](dashboard.snapshot.schema.json) and [TypeScript/Zod source](../src/lib/schema.ts) describe the browser payload. Registered items load without a phone; camera, pose and guidance require phone telemetry.

| Interface                  | Required behavior                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /dashboard/snapshot`  | Return one complete `dashboard.snapshot` envelope.                                                                                         |
| `WS /events`               | Immediately send a fresh complete snapshot; send another at least every second. In between, relay the phone's sounds as `dashboard.sound`. |
| `POST /dashboard/commands` | Accept Find / Stop, return **202** `{ "commandId": "same-id", "status": "pending" }`.                                                      |
| Media URLs in snapshots    | Serve upright images and playable audio to the same browser session.                                                                       |

1. **Full snapshots only.** Each envelope has `schemaVersion: 1`, `streamId`, increasing `sequence`, UTC `sentAt`, and complete `data`. New arrays replace old arrays. Change `streamId` when sequence numbers reset. Socket reconnect must receive current state, including events missed during the disconnect.
2. **One coordinate convention.** Meters; world X goes right, Z goes down in the map. Y is height. Yaw is clockwise from −Z. Every usable position belongs to a `worldMapId`. The session, displayed map and wearer must share a non-null map ID before the browser shows a live position, target line or enabled Recenter. Unknown map, pose, location, camera or label is `null`. Never send mock geometry in live mode. Optional `map.fixtures` supplies known furniture rectangles (`id`, `name`, `kind: table | sofa | storage`, `x`, `z`, positive `width`, positive `depth`); omit it if unavailable.
3. **The phone owns guidance.** Find request: `{ "commandId": "unique-id", "deviceId": "iphone-id", "type": "find", "itemId": "item-id" }`. Stop omits `itemId` and uses `"type": "stop"`. Deduplicate by `commandId`. HTTP 202 means queued. Relay to the phone; publish matching `lastCommand` as accepted/completed/rejected. Publish phone navigation state in the same snapshot. The browser waits up to 10 seconds and reuses the same ID when retrying within the same device/session. Changing `data.session.id` or `data.session.deviceId` invalidates pending/failed requests and their timers; new actions receive new IDs.
4. **Camera image and boxes are one unit.** Each `frameId` points to an immutable upright image. Publish `widthPx`, `heightPx`, capture time, `imageUrl` and matching `[xMin,yMin,xMax,yMax]` boxes together. The browser uses a contained image with an SVG in the same coordinate space. A failed image or mismatched dimensions hides its boxes. Keep image URLs accessible for at least 10 seconds. Prefer one JPEG/second, not base64 in snapshots.
5. **Preserve memory.** Keep objects when out of view or disconnected. Update `lastSeen` only with newer observations. Publish moved sightings in `recentMemory`. A saved Photon label and its item must arrive in the same snapshot. Dashboard registration is read-only; requests and replies go through Photon.
6. **Report actual device health.** Mark the phone disconnected after 5 seconds without telemetry; include `normal | limited | relocalizing | unavailable` tracking. Browser snapshots older than 3 seconds hide live guidance; stale phone/pose/navigation also hides cues. After more than 10 seconds without a valid newer snapshot, the browser closes the silent socket and refetches through its existing reconnect backoff. The wait is also bounded when no initial snapshot arrives. Authorization failures stop recovery attempts. A browser disconnect does not stop phone audio. No camera frame for 10 seconds shows a waiting state.
7. **Use stable errors.** HTTP 400 invalid request; 401/403 access denied; 404 unknown item; 409 disconnected/pending/location unavailable. Body: `{ "error": { "code": "phone_disconnected", "message": "iPhone is disconnected." } }`. Reject a command with `lastCommand.reason` if the phone does not acknowledge in 10 seconds.
8. **Keep one origin.** The browser calls `/api/...`. Vite proxies this to `http://127.0.0.1:8000/...` in development. For deployment, serve the static `frontend/dist` and proxy `/api` HTTP and WebSockets to FastAPI. A snapshot media URL `/media/a.jpg` becomes `/api/media/a.jpg`; absolute HTTP(S) media URLs pass through. Use the same session policy for all routes. The existing prototype's test-only auth bypass is not the dashboard integration strategy.

If separate origins are required, set `VITE_API_BASE_URL` to the FastAPI origin, configure the exact dashboard origin with credentials, and validate WebSocket origins/session access too. See [FastAPI CORS](https://fastapi.tiangolo.com/tutorial/cors/) and [FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/).

A useful integration check is to confirm Objects loads, publish a newer sighting through `/events`, then send Find and acknowledge its command ID from the phone. An example fixture verifies rendering only; real phone guidance and headphone playback need device checks.
