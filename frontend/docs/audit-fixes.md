# Frontend audit fixes — October 17, 2026

Fixed the four actionable bugs from the supplied frontend audit while preserving the existing V3 design and iOS work.

| Finding                                | Corrected behavior                                                                                                                                                                                                                                                                                                                                                         | Regression coverage                                                                                                                                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Obsolete map position shown as live    | Live position requires matching non-null session/map/wearer IDs, current phone telemetry, normal tracking and a fresh pose. Mismatches suppress the wearer marker, target line, badge and Recenter while retaining remembered descriptions. MapView also checks identity independently of its caller.                                                                      | Unit/render cases for consistent/reset/missing maps, stale pose/phone, tracking loss and offline state; browser cases for session and wearer resets.                                                        |
| Retry targets a previous phone         | Pending/failed commands and timers are cleared when device or session identity changes. Retry/reuse checks the active identity; new actions receive fresh IDs. Same-device/session uncertain retries keep their original ID. Late old errors/acknowledgements cannot alter the replacement request.                                                                        | Unit cases for both device and session replacement, pending and failed requests, late results and same-scope stream reconnect.                                                                              |
| Silent socket never recovers           | Stale status still starts after 3 seconds. After more than 10 seconds without snapshot progress, the socket is detached/closed and the existing backoff refetches state before reconnecting. This also covers a socket with no first valid snapshot. Old socket events are ignored, duplicate reconnects are guarded, disposal cancels recovery and 401/403 stops retries. | Fake-timer tests for silence, first-snapshot timeout, duplicate close/error, disposal and authorization; a real-browser test waits through silence and verifies automatic refetch/recovery without refresh. |
| Missing camera looks like failed image | A null camera shows **Waiting for camera**. Only a non-null frame identity can match a recorded image failure; offline still shows **Camera disconnected** and a new frame can recover.                                                                                                                                                                                    | Unit/render null/offline cases; browser flow through absent camera, failed image, absent camera again, recovered frame and disconnection.                                                                   |

Validation: `npm run check` passed formatting, lint, generated-schema check, TypeScript/production build, **52 unit tests** and **22 browser tests**, including accessibility scans and 1440/768/390 px layouts. `git diff --check` passed.

The separate `/v1` server-to-dashboard adapter and phone Find/Stop forwarding remain unimplemented, as already recorded in [fastapi-handoff.md](fastapi-handoff.md). Browser API tests mock the dashboard contract and do not establish real phone/server integration. No backend wire formats or authentication changed.
